## 진행 원칙 3가지

1. **"동작 확인 방법"을 통과하지 못하면 다음 Step으로 넘어가지 않는다.**
2. **한 Step이 끝나면 개발 로그를 쓴다.** (블로그 초안은 프로젝트 공부 세션 담당 — CLAUDE.md 5장)
3. **그 다음 커밋 + push 한다.** (되돌아갈 지점 만들기 + 다른 컴퓨터로 이어가기 — CLAUDE.md 6장)

> 순서는 항상 **① 동작 확인 → ② 개발 로그 → ③ 커밋·push** 입니다.
> 한 Step에 백엔드·프론트 작업이 둘 다 있으면, **각 세션이 자기 몫을 끝낼 때마다** 따로 개발 로그를 쓰고 커밋합니다.


## Step 2 — 로그인/인증 🔐

| 담당 | 양쪽 |
|---|---|

**프론트엔드**
1. `@supabase/supabase-js`, `@supabase/ssr` 설치
2. `.env.local`에 Supabase URL / publishable key
3. `/login` 페이지 — 이메일 회원가입/로그인, 로그아웃
4. 로그인 안 한 상태로 보호된 페이지(`/new`, `/story/...`, `/library`) 접근 시 `/login`으로 보내기
   - ⚠️ Next.js 16에서는 파일 이름이 **`src/proxy.ts`** 입니다. (예전 강의·블로그의 `middleware.ts`는 옛 이름)
5. ⚠️ Supabase는 **로그인에만** 씁니다. `supabase.from(...)`으로 DB를 읽는 코드는 쓰지 않습니다. (01번 원칙 6)

**백엔드**
1. `PyJWT[crypto]` 설치 (버전 고정)
2. JWT 검증 의존성 `get_current_user` — JWKS로 서명 확인 + `aud="authenticated"` + `iss="<SUPABASE_URL>/auth/v1"` + 만료 확인. 실패 시 401 `UNAUTHORIZED`
3. `GET /api/v1/me` (프로필 없으면 생성 — 보조 안전장치)
4. CORS 설정 (04번 문서 7장, `CORS_ORIGINS` 환경변수)
5. 테스트용 토큰 발급 스크립트 `backend/scripts/get_test_token.py` → 프론트 없이도 Swagger UI(`/docs`)에서 테스트

**동작 확인**
- 회원가입 → Supabase Auth 대시보드에 유저가 보이고, `profiles`에도 한 줄 생긴다
- 로그아웃 상태로 `/library` 주소를 치면 `/login`으로 이동한다
- 테스트 토큰으로 `GET /api/v1/me` → 200 / 토큰 없이·엉터리 토큰 → 401, 응답 모양이 `{"error": {...}}`

> ⚠️ **여기가 가장 많이 막히는 구간입니다.** JWT 검증은 비전공자에게 어렵습니다.
> 하루 안에 안 끝나도 정상입니다. 여기를 대충 넘기면 나중에 전부 다시 짜야 합니다.

## Step 3 — 타입 자동생성 + 목(mock) API 🔗

| 담당 | 양쪽 |
|---|---|

이 Step의 목적: **프론트가 백엔드를 기다리지 않고 일할 수 있게 만들기.**

**백엔드**
1. 04번 문서의 **모든 API를 Pydantic 모델로만** 정의 — **6장 모델 이름표 그대로**, 코드값은 `Literal`
2. 규칙 파일 `app/game/rules.py` — 02번 문서의 칩 목록·태도 표·범위·상한·기본 선택지를 **파이썬 상수로** 옮김
3. 각 엔드포인트를 **가짜 데이터**를 돌려주는 껍데기로 구현
   - `GET /meta/onboarding-options`는 가짜가 아니라 **진짜** (`rules.py`에서)
   - 프롤로그·행동·에필로그 3개는 **가짜 SSE 스트림**(정해진 문장을 0.1초 간격으로 조각내 흘려보냄) → 프론트가 SSE 처리를 미리 만들 수 있게
4. 전역 예외 처리기 3개 (04번 문서 0장 — 422를 400으로, `{"detail"}`을 `{"error"}`로)
5. SSE 타입 문서용 엔드포인트 `GET /api/v1/_schema/sse-events` (04번 문서 6장)
6. `FastAPI(separate_input_output_schemas=False)` 설정 후 `/openapi.json` 확인

**프론트엔드**
1. `openapi-typescript` 설치 + `package.json`에 `"gen:api"` 스크립트 → `npm run gen:api`
2. `src/types/index.ts` — 자동 생성 타입에 짧은 별명만 붙이기 (모양을 새로 정의하지 않음)
3. `src/lib/api-client.ts` — 토큰을 자동으로 붙이고, `{"error"}` 응답을 공통 처리하는 fetch 래퍼 (401이면 `/login`)
4. `src/lib/sse.ts` — SSE 파서 **하나** (04번 문서 5-5: 빈 줄 구분, `:` 주석 무시, `TextDecoder` stream 모드). 프롤로그·행동·에필로그가 공용으로 씀
5. 생성된 타입으로 API 함수 작성

**동작 확인**
- 프론트에서 `getOnboardingOptions()`를 부르면 칩 목록이 온다
- 가짜 행동 스트림을 받아 콘솔에 `turn_started` → `narration_delta` 여러 번 → `turn_completed` 가 순서대로 찍힌다
- 백엔드에서 Pydantic 필드명을 바꾸고 타입을 재생성하면, 프론트에서 **컴파일 에러가 난다** ← 이게 성공 신호

> 💡 **"에러가 나는 게 성공"인 이유**: 어긋남을 배포 전에 잡아준다는 뜻입니다.
> 이 장치가 없으면 어긋남을 **유저가 발견**합니다.

3. soft 상한(30) 이후 매듭 지시 + `closure_suggested` 강제, 최대 턴(40) `TURN_LIMIT_REACHED`
4. 목록·상세의 `mood_history`, `mood_valences`, `attitude_counts` 계산

**프론트엔드**
1. "오늘은 여기까지 · 마침표 찍기" (확인 한 번), `closure_suggested` 은은한 강조, 최대 턴 안내
2. 마지막 페이지 화면: 에필로그 → 제목 → 하루의 감정 파동 → 오늘의 태도 (09번 문서 4-3)
3. `/library` 완성: 서재 카드(제목·날짜·작은 파동·태도), 지우기, 완성작 읽기 전용 모드

**동작 확인**: 3턴쯤 진행한 뒤 마침표를 찍으면 에필로그와 제목이 뜨고, 서재에 꽂힌다. 완성작은 선택지·입력창 없이 처음부터 끝까지 읽힌다.

## Step 9 — 입력·행동 해석기 (안전장치) + 퓨샷 5종 🛡️

| 담당 | 백엔드 중심 |
|---|---|

1. A. 입력 해석기 — 이야기 만들 때 의미 검사·"현실로 번역"·`flavor_code`·시작 감정 (05번 문서 3장 A)
2. B. 행동 해석기 — 직접 입력의 안전·현실성·태도·주입 시도 판정, 위기 신호면 `safety_notice` (05번 문서 3장 B)
3. 퓨샷 파일 5종 완성 (백엔드 세션 초안 → **사용자가 문체를 다듬어 확정**)
4. 프론트: `safety_notice` 안내 상자, 이야기 만들기 대기 표시(1~3초) (09번 문서 5장)

**동작 확인**: 대상에 "마법사"를 넣으면 현실의 인물로 해석된 프롤로그가 나온다. 부적절한 입력은 부드럽게 거절된다. 위기 신호가 담긴 문장을 넣으면 이야기는 다정하게 이어지고 도움 안내가 조용히 뜬다.

> ⚠️ **이 Step은 배포(Step 11) 전에 반드시 끝나야 합니다.** 감정을 다루는 게임이라 안전장치 없이 공개하지 않습니다.

| 4 | 한글 명조 글꼴 파일이 커서 느림 | 필요한 굵기만, 가능하면 서브셋 글꼴 사용 |
