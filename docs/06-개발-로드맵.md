# 06. 개발 로드맵 (Step 0 ~ 12)

> 🎯 **"무엇부터 할지"에 대한 답입니다.**
> 💡 각 Step은 하루 이내에 끝나는 크기이고, **끝나면 눈으로 확인할 수 있는 결과**가 있습니다.
> 💡 순서를 바꾸면 안 됩니다. 앞 단계가 뒷 단계의 재료입니다.

---

## 진행 원칙 3가지

1. **한 Step이 끝나면 반드시 커밋한다.** (되돌아갈 지점 만들기)
2. **한 Step이 끝나면 개발 로그 + 블로그 초안을 쓴다.** (CLAUDE.md 5장 규칙)
3. **"동작 확인 방법"을 통과하지 못하면 다음 Step으로 넘어가지 않는다.**

---

## 전체 지도

```
[기반 공사]         Step 1  DB 스키마
                    Step 2  로그인/인증
                    Step 3  타입 자동생성 + 목(mock) API
                            ↓ 여기까지가 "안 보이지만 제일 중요한 것"
[게임 준비]         Step 4  캐릭터 생성
                    Step 5  시나리오 선택 + 세션 시작
                            ↓ 여기서 AI 없이도 "게임 시작" 화면이 돌아감
[AI 투입]           Step 6  GM 한 명 (동기 응답)
                    Step 7  스트리밍 (타이핑 효과)
                    Step 8  주사위 + 상태 관리 (멀티 에이전트)
                    Step 9  장기 기억 (pgvector)
                            ↓ 여기가 MVP 완성
[확장/마무리]       Step 10 NPC 에이전트
                    Step 11 배포
                    Step 12 다듬기
```

## Step 1 — DB 스키마 만들기 🗄️

| 담당 | 백엔드 세션 |
|---|---|
| 산출물 | `supabase/migrations/0001_init.sql`, `0002_rls.sql`, `0003_seed.sql` |

**할 일**
1. Supabase 프로젝트에서 `pgvector` 확장 켜기
2. 03번 문서의 7개 테이블 생성 SQL 작성
3. RLS 정책 SQL 작성
4. 샘플 시나리오 2개 INSERT
5. Supabase SQL Editor에서 실행

**동작 확인**
- Supabase Table Editor에 테이블 7개가 보인다
- 다른 계정으로 로그인했을 때 남의 `characters`가 안 보인다 (RLS 테스트)

**프론트엔드 세션은 이 Step에 할 일 없음** → 대신 화면 와이어프레임을 종이에 그려둔다

## Step 2 — 로그인/인증 🔐

| 담당 | 양쪽 |
|---|---|

**프론트엔드**
1. `@supabase/supabase-js`, `@supabase/ssr` 설치
2. `.env.local`에 Supabase URL / publishable key
3. `/login` 페이지 — 이메일 회원가입/로그인
4. 로그인 안 한 상태로 `/play` 접근 시 `/login`으로 보내기 (middleware)
5. 로그아웃 버튼

**백엔드**
1. JWT 검증 의존성 `get_current_user` 구현 (JWKS로 서명 확인)
2. `GET /api/v1/me` 구현 (프로필 없으면 자동 생성)
3. CORS 설정

**동작 확인**
- 회원가입 → Supabase Auth 대시보드에 유저가 보인다
- 로그인 후 `GET /api/v1/me`가 200을 준다
- 토큰 없이 부르면 401을 준다

> ⚠️ **여기가 가장 많이 막히는 구간입니다.** JWT 검증은 비전공자에게 어렵습니다.
> 하루 안에 안 끝나도 정상입니다. 여기를 대충 넘기면 나중에 전부 다시 짜야 합니다.

## Step 3 — 타입 자동생성 + 목(mock) API 🔗

| 담당 | 양쪽 |
|---|---|

이 Step의 목적: **프론트가 백엔드를 기다리지 않고 일할 수 있게 만들기.**

**백엔드**
1. 04번 문서의 **모든 API를 Pydantic 모델로만** 정의
2. 각 엔드포인트를 **가짜 데이터**를 돌려주는 껍데기로 구현
3. 공통 에러 응답 핸들러 구현
4. `/openapi.json`이 나오는지 확인

**프론트엔드**
1. `npx openapi-typescript http://localhost:8000/openapi.json -o src/types/api.ts`
2. `src/lib/api-client.ts` — 토큰을 자동으로 붙이고, 에러를 공통 처리하는 fetch 래퍼
3. 생성된 타입으로 API 함수 작성

**동작 확인**
- 프론트에서 `getCharacters()`를 부르면 가짜 캐릭터 목록이 온다
- 백엔드에서 Pydantic 필드명을 바꾸고 타입을 재생성하면, 프론트에서 **컴파일 에러가 난다** ← 이게 성공 신호

> 💡 **"에러가 나는 게 성공"인 이유**: 어긋남을 배포 전에 잡아준다는 뜻입니다.
> 이 장치가 없으면 어긋남을 **유저가 발견**합니다.

## Step 4 — 캐릭터 생성 🧑

| 담당 | 양쪽 |
|---|---|

**백엔드**: `POST/GET/DELETE /api/v1/characters` 실제 DB 연동 + 검증(합계 15)
**프론트엔드**: `/characters/new` 능력치 배분 UI (남은 포인트 표시), `/characters` 목록

**동작 확인**: 캐릭터를 만들고 새로고침해도 남아있다. 합계 15가 아니면 저장 버튼이 안 눌린다.

---

## Step 5 — 시나리오 선택 + 세션 시작 🎬

| 담당 | 양쪽 |
|---|---|

**백엔드**: `GET /scenarios`, `POST/GET /sessions`, `POST /sessions/{id}/end`
**프론트엔드**: 시나리오 카드 목록 → 캐릭터 선택 → 시작 → `/play/{sessionId}`로 이동
   - `/play` 화면 레이아웃: 좌측 이야기 영역 / 우측 상태 패널(HP·멘탈·소지금·인벤토리) / 하단 입력창
   - 오프닝 서술 표시. 입력창은 아직 눌러도 아무 일 없음

**동작 확인**: 게임 시작을 누르면 1초 안에 오프닝 장면이 뜬다. 새로고침해도 이어진다.

> 🎉 **여기까지가 "AI 없는 게임 껍데기 완성"입니다.**

---

## Step 6 — GM 한 명 붙이기 (동기) 🤖

| 담당 | 백엔드 중심 |
|---|---|

1. `app/agents/` 에 LangGraph 그래프 생성 — **이야기꾼 노드 하나만**
2. `POST /sessions/{id}/actions` 를 **일단 SSE 없이 일반 JSON**으로 구현
3. 턴 잠금(`processing`) + 멱등성(`client_action_id`) 구현
4. 프론트: 입력 → 로딩 스피너 → 서술 추가

**동작 확인**: 행동을 입력하면 10초쯤 뒤에 GM 서술이 나온다. 전송 버튼을 연타해도 턴이 1개만 늘어난다.

> 💡 **왜 스트리밍을 먼저 안 하나?** 스트리밍은 디버깅이 훨씬 어렵습니다.
> 먼저 "AI가 제대로 답하는가"를 확인하고, 그 다음에 "예쁘게 흘려보내기"를 붙입니다.

---

## Step 7 — SSE 스트리밍 ⚡

| 담당 | 양쪽 |
|---|---|

**백엔드**: 04번 6장의 이벤트 규격대로 `StreamingResponse` 구현 (`turn_started` / `narration_delta` / `turn_completed` / `error`)
**프론트엔드**: `fetch` + `ReadableStream`으로 SSE 파싱 (`EventSource`는 헤더를 못 붙여서 쓸 수 없음), `AbortController`, 타임아웃, 끊김 복구

**동작 확인**: 글자가 한 글자씩 나타난다. 도중에 페이지를 나가도 에러가 안 뜬다.

## Step 8 — 주사위 + 상태 관리 (멀티 에이전트) 🎲

| 담당 | 백엔드 중심 |
|---|---|

1. 판정관 노드 (구조화 출력)
2. 주사위 노드 (파이썬)
3. 기록원 노드 (구조화 출력)
4. 검증/반영 노드 (상한 clamp, 게임오버 판정)
5. 프론트: 주사위 연출 UI + 상태 패널 실시간 증감

**동작 확인**: "경비원을 설득한다" → 주사위 연출 → 실패하면 서술도 실패로 나온다. HP가 깎이면 우측 패널이 줄어든다. 0이 되면 게임오버 화면.
