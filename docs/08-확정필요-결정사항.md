## ① 플레이 인원 — 1인 vs 여러 명 동시

| 선택지 | 영향 |
|---|---|
| **✅ 가정: 1인 플레이** | SSE로 충분. DB 단순. MVP 2~3주 |
| 여러 명 동시 | WebSocket 필요, 턴 순서 관리, 실시간 동기화 → 작업량 3배 |

> 💡 멀티플레이는 나중에 붙일 수 있지만, **통신 방식(SSE→WebSocket)을 갈아엎어야** 합니다.
> 처음부터 멀티가 목표라면 지금 말씀해주세요.

## ② AI 모델 제공자

현재 `backend/requirements.txt`에는 `langchain-openai`가 들어 있습니다.

| 선택지 | 비고 |
|---|---|
| **✅ 가정: OpenAI** | 이미 패키지가 들어있음. 임베딩까지 한 곳에서 해결 |
| Anthropic Claude | 한국어 서술 품질이 좋다는 평. 임베딩은 별도 필요 |
| 둘 다 (역할별 분리) | 이야기꾼=Claude, 판정관=저가 모델 등. 설정이 복잡해짐 |

> ⚠️ **임베딩 모델은 특히 중요합니다.** DB의 `vector(1536)` 차원이 모델에 묶여 있어서,
> 나중에 바꾸면 `memories` 테이블을 비우고 다시 만들어야 합니다. (03번 문서 2-6)

**필요한 것**: 해당 서비스의 API 키 발급 + 결제수단 등록 여부

## ③ 로그인 방식

| 선택지 | 비고 |
|---|---|
| **✅ 가정: 이메일 + 비밀번호** | 가장 단순. Supabase 기본 제공 |
| 카카오/구글 소셜 로그인 | 유저 편의성 좋음. OAuth 설정 작업 추가 (반나절~1일) |
| 익명 로그인(게스트) | 회원가입 없이 바로 플레이. 데이터 유실 위험 |

> 💡 MVP는 이메일로 가고, Step 12에서 소셜 로그인을 추가하는 걸 권합니다.
> Supabase Auth는 나중에 방식을 추가해도 기존 코드가 안 깨집니다. (드물게 안전한 케이스)

## ④ 시나리오를 누가 만드나

| 선택지 | 영향 |
|---|---|
| **✅ 가정: 운영자(나)가 미리 만든 것만** | `scenarios` 테이블에 SQL로 넣음. 단순 |
| 유저가 직접 만들어 플레이 | 시나리오 편집 UI + 검열/신고 기능 필요 |
| AI가 자동 생성 | 재미있지만 품질 편차 큼 |

## ⑤ 게임 오버 후 이어하기

| 선택지 | 영향 |
|---|---|
| **✅ 가정: 종료 후 되돌리기 없음** | 단순. TRPG의 긴장감 유지 |
| 이전 턴으로 되돌리기(세이브 로드) | `turns` 스냅샷 저장 필요. 상태 복원 로직 복잡 |

## ⑥ 서술 길이와 말투

| 항목 | 가정값 |
|---|---|
| 한 턴 서술 길이 | **150~400자** (스마트폰 한 화면) |
| 시점 | **2인칭 "당신은..."** |
| 문체 | 소설체. 과하지 않은 묘사 |
| 수위 | **12세 이용가 수준** (유혈/공포 묘사는 은유적으로) |

> ⚠️ 수위는 나중에 바꾸기 어렵습니다. 시나리오 내용과 프롬프트가 전부 여기 맞춰집니다.
