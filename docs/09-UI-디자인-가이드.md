# 09. UI 디자인 가이드 (여백의 화면 규칙)

> 🎯 **"소설책을 한 장씩 차분히 읽어 내려가는 독서 경험"** (`GAME_CONCEPT.md` 2장)
> 💡 이 게임의 화면은 **게임기가 아니라 책**입니다. 버튼·게이지·말풍선이 떠오르면 방향이 틀린 것입니다.
> 이 문서는 프론트엔드 세션이 화면을 만들 때 따르는 규칙입니다. (값을 바꾸고 싶으면 아키텍처 세션에 요청)

---

## 1. 절대 하지 않는 것

| ❌ 금지 | 이유 |
|---|---|
| 채팅 앱 같은 **말풍선** | 이건 대화가 아니라 책. 서술은 본문 문단으로 흐른다 |
| 쨍한 색의 큰 **버튼** | 기획서 "쨍하고 화려한 버튼 배제" |
| HP바·게이지·숫자 같은 **게임 HUD** | 감정은 숫자가 아니라 은은한 선으로만 |
| 빨간 에러 토스트, 흔들림 효과 | 몰입을 깨는 소음 |
| 본문 속 이모지 | 책에는 이모지가 없다 |

## 2. 화면 지도 (라우트)

| 주소 | 화면 | 로그인 필요 |
|---|---|---|
| `/` | 첫 화면. 비로그인: 한 줄 소개 + 로그인 / 로그인: "새 이야기 쓰기" + 이어 쓰는 중 + 서재 바로가기 | 아니오 |
| `/login` | 로그인·회원가입 | 아니오 |
| `/new` | **온보딩** — 4가지 질문 | 예 |
| `/story/[id]` | **읽기·쓰기 화면** (진행 중이면 쓰기, 완성작이면 읽기 전용) | 예 |
| `/library` | **여백의 서재** — 완성된 이야기 목록 | 예 |

- 로그인 필요 페이지는 `src/proxy.ts`에서 막는다. (Next.js 16. 옛 이름 `middleware.ts` 아님)
- 완성작도 `/story/[id]`에서 연다. 주소를 하나로 두면 "이어 쓰던 이야기 → 완성작"으로 바뀌어도 링크가 그대로다.

## 3. 디자인 토큰 (색·글꼴·간격)

`src/app/globals.css`의 Tailwind v4 `@theme`에 **이 이름 그대로** 등록하고, 컴포넌트에서는 이 이름만 쓴다. (색 코드를 컴포넌트에 직접 적지 않음)

### 색
| 토큰 | 값 (초안) | 쓰는 곳 |
|---|---|---|
| `--color-paper` | `#FAF7F0` | 기본 배경 (크림빛 종이) |
| `--color-paper-deep` | `#F2ECE0` | 카드·입력창 배경, 구분 영역 |
| `--color-ink` | `#2A2926` | 본문 글자 (딥 차콜) |
| `--color-ink-soft` | `#5E5B55` | 보조 글자 (플레이어 입력, 설명) |
| `--color-ink-faint` | `#9B968C` | 아주 옅은 글자 (태도 라벨, 글자 수, 날짜) |
| `--color-line` | `#E3DCCF` | 가는 구분선 |
| `--color-accent` | `#7A5F43` | 유일한 강조색 (먹빛 세피아). 링크 밑줄, 맺기 강조, 파동 선 |
| `--color-notice` | `#EEF1EA` | 안전 안내 상자 배경 (차분한 연녹회색) |

- 본문 글자와 배경의 명암 대비는 **4.5:1 이상** 유지 (접근성)
- **다크 모드는 MVP에서 만들지 않는다.** (화이트 모드 메인)

### 글꼴
| 용도 | 글꼴 | 비고 |
|---|---|---|
| 본문(서술) | 명조 계열 (예: Noto Serif KR) | 소설책 느낌 |
| UI(메뉴·라벨·입력) | 고딕 계열 (예: Pretendard) | 작고 조용하게 |

- 글꼴 파일은 **프로젝트 안에 넣고 `next/font/local`로** 불러온다. (빌드할 때 외부 글꼴 서버에 접속하지 않도록 — 프론트 README의 기존 방침과 같음)
- 무료 공개 라이선스(OFL) 글꼴만 쓴다.

### 본문 조판
| 항목 | 값 |
|---|---|
| 글자 크기 | 모바일 17px / 데스크톱 18px |
| 줄 간격 | 1.9 |
| 본문 폭 | 최대 34em (약 600px), 가운데 정렬 |
| 문단 간격 | 1.2em |
| 좌우 여백 | 최소 20px |

## 4. 화면별 규칙

### 4-1. 온보딩 (`/new`)
- **한 화면에 질문 하나씩**, 책장을 넘기듯 4번 넘긴다. (대상 → 감정 → 상황 → 장르의 결)
- 질문 문장·칩·글자 수는 `GET /api/v1/meta/onboarding-options`에서 받는다. (04번 문서 3장, 코드에 적지 않음)
- 칩은 **작은 텍스트 알약**(옅은 테두리). 고르면 테두리만 `accent`로.
- 칩 아래 밑줄 한 줄짜리 **"직접 적기"** 입력. 칩을 고르면 입력칸에 그 문구가 들어가고, 고친 순간 칩 선택은 풀린다(`preset_id = null`).
- 위쪽에 `1 / 4` 같은 진행 표시를 `ink-faint`로 작게.
- 마지막 장의 버튼 문구: **"이야기 시작하기"**. 누르면 "이야기를 준비하는 중..." (Step 9부터 1~3초 걸릴 수 있음)

### 4-2. 읽기·쓰기 (`/story/[id]`)
화면 구성 (위에서 아래로):
```
  (작게) 3년 차 회사원 · 지독한 권태와 짜증 · 월요일 아침 출근길        ← premise, ink-faint
  ───────────────────────────────
  [프롤로그 서술 문단들]
                      · · ·                                     ← 턴 구분 장식
  — “괜찮습니다.” 웃으며 삼킨다   참아내기                        ← 플레이어 입력, ink-soft + 태도 라벨 ink-faint
  [다음 서술 문단들]  ▍                                          ← 스트리밍 중 커서
                      · · ·
  — “괜찮습니다.” 웃으며 삼킨다          참아내기                 ← 선택지 (텍스트 줄)
  — 대답 대신 이어폰을 꽂는다             피하기
  ___________________________________ 직접 적기                  ← 밑줄 입력 (200자)
                                         오늘은 여기까지 · 마침표 찍기   ← 맺기 (작은 텍스트 링크)
```
- **서술**: 말풍선 없이 본문 문단. `narration_delta`가 오는 대로 이어 붙이고, 끝에 옅은 커서. 서술 안의 `\n\n`은 문단 나눔.
- **플레이어 입력**: 서술 사이에 줄표(—)로 시작하는 한 줄, `ink-soft`. 선택지였으면 옆에 태도 라벨(`ink-faint`).
- **선택지**: 버튼이 아니라 **줄표로 시작하는 텍스트 줄**. 마우스를 올리면 `accent` 밑줄. 오른쪽에 태도 라벨. 키보드 `1`·`2`·`3`으로도 고를 수 있게.
- **직접 입력**: 밑줄 한 줄. 글자 수는 `ink-faint`로 `37 / 200`. Enter로 보내기 (Shift+Enter 줄바꿈 없음)
- **여기서 맺기**: 작은 텍스트 링크. `can_close`가 `false`면 숨김. `closure_suggested`가 `true`면 글자를 `accent`로 바꾸고 옆에 작은 점 하나 — **깜빡이거나 튀지 않는다.** 누르면 "오늘 이야기를 여기서 맺을까요?" 확인 한 번.
- **쓰는 중**: 선택지·입력·맺기를 흐리게(비활성). 첫 글자 전에는 `· · ·` 세 점이 천천히 숨 쉬듯.
- **최대 턴 도달** (`turn_limit_reached`): 선택지·입력을 숨기고 "이 이야기의 마지막 장까지 왔어요." + 마침표 찍기만.
- **감정의 파동**: 데스크톱은 본문 왼쪽 여백, 모바일은 상단 설정 줄 아래에 **얇은 선 하나**(`accent`, 1px). 숫자·축·라벨 없음. 새 턴이 끝나면 선이 부드럽게 한 칸 이어진다.
- **이야기 상태**(`story_state`): 기본은 숨김. 설정 줄을 누르면 장소·시각·등장인물이 작게 펼쳐진다.
- 이전 턴은 위로 스크롤하면 20개씩 더 불러온다. (`GET /turns`의 `has_more`)

### 4-3. 마지막 페이지 (에필로그 후)
- `turn_completed`의 `session.status = completed`를 받으면 전환.
- 에필로그 서술 아래에: **제목**(본문보다 조금 크게, 명조) → 하루 전체의 **감정의 파동**(조금 크게, 턴마다 점, 점에 마우스를 올리면 감정 이름) → **오늘의 태도**("참아내기 5 · 받아치기 1" 한 줄)
- 'THE END' 같은 자막 없음. 맨 아래 작은 링크: "서재에 꽂아두기" (→ `/library`), "새 이야기 쓰기"

### 4-4. 여백의 서재 (`/library`)
- 책등처럼 **세로로 쌓인 목록** 또는 카드 격자. 카드 한 장 = 제목, 완성한 날짜, 설정 한 줄, 작은 파동 선(`mood_valences`), 태도 한 줄
- 비어 있으면: "아직 꽂힌 이야기가 없어요. 오늘의 이야기를 써볼까요?"
- 카드마다 조용한 "지우기" (확인 한 번)

## 5. 안내·오류·안전 표시

| 경우 | 모양 |
|---|---|
| 요청 거절(4xx)·스트림 `error` | 입력창 바로 위 한 줄, `ink-soft`, 부드러운 문장 (`error.message` 그대로). 빨간색 금지 |
| 연결 끊김 | "이야기가 잠시 끊겼어요. 다시 불러올까요?" + 다시 불러오기 링크 |
| `safety_notice = true` | 그 턴 서술 바로 아래 `notice` 색 상자. 이야기를 멈추지 않고 조용히:<br>"혹시 지금 정말 많이 힘들다면, 혼자 견디지 않아도 괜찮아요. 자살예방상담전화 **109** (24시간)"<br>(번호는 배포 전에 다시 확인) |
| 서버 깨우는 중 (배포 후 첫 요청) | "책장을 펼치는 중이에요..." (Step 11) |

## 6. 움직임

- 새 문단·선택지는 **200~300ms 페이드인**만. 튀거나 미끄러지는 효과 없음
- 스트리밍 커서는 천천히 깜빡이는 얇은 막대
- 운영체제의 "동작 줄이기"(`prefers-reduced-motion`) 설정이 켜져 있으면 모든 애니메이션을 끈다

---

## 7. 반응형·접근성

- **모바일 먼저** 만든다. (출근길 지하철에서 읽는 게임)
- 모든 조작은 키보드로 가능, 포커스 테두리는 지우지 않는다 (`accent` 색으로 은은하게)
- 선택지·링크의 터치 영역은 최소 44px 높이

---

## 8. Shadcn UI 사용 원칙

- Shadcn은 **확인 창(Dialog)·툴팁 같은 기능 부품**에만 쓰고, 기본 모양은 위 토큰으로 다시 입힌다.
- 기본 버튼 컴포넌트를 그대로 쓰지 않는다. (쨍한 버튼 금지 원칙)
