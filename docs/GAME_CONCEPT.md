# AI TRPG Game Master - 프로젝트 기획 및 서사 설계서

## 1. 프로젝트 핵심 철학 (Core Philosophy)
- **장르:** 현대 서울 배경의 현실 밀착형 텍스트 RPG (판타지/오컬트 배제)
- **지향점:** 거대한 세계관이나 영웅주의가 아닌, **평범한 일상 속에서 마주하는 날것 그대로의 감정(기쁜 일, 슬픈 일, 짜증, 무기력, 미세한 관계의 파열음)**에 집중한다.
- **스토리의 성격:** 고정된 메인 시나리오나 레일로드 방식이 아니라, **사용자의 입력에 따라 LLM이 매번 실시간으로 새로운 인생 드라마를 빚어내는 동적 서사(Dynamic Narrative)**를 추구한다.

## 2. UI/UX 톤앤매너 (Design Concept)
- **콘셉트:** "소설책을 한 장씩 넘기며 읽는 듯한 몰입감"
- **테마:** **화이트 모드 메인** (눈이 편안한 미색/크림빛 배경 + 차분한 딥 차콜/검은색 폰트)
- **연출:** 쨍하고 화려한 버튼 UI 지양. 텍스트가 정갈하게 배치되며, LLM이 답변을 내려줄 때 마치 책장이 적혀 내려가듯 타이핑되는 스트리밍(Streaming) 효과 적용.

## 3. 온보딩(첫 화면) 입력 구조
게임 시작 시, 플레이어에게 복잡한 능력치가 아닌 4가지 핵심 요소를 입력받아 LLM 프롬프트의 뼈대로 사용한다.
1. **대상 (Who):** 플레이어의 페르소나 (예: 3년 차 회사원, 취업준비생, 프리랜서 등)
2. **감정 (Emotion):** 오늘의 주된 감정 상태 (예: 무기력, 짜증, 은근한 불안, 덤덤함 등)
3. **상황 (Context):** 시공간적 배경 및 화두 (예: 비 오는 밤 2호선 지하철 안, 텅 빈 원룸 등)
4. **장르의 결 (Flavor):** 오늘 전개될 이야기의 분위기 (예: 일상/드라마, 서늘한 서스펜스, 씁쓸한 블랙코미디 등)

## 4. LLM 내러티브 생성 및 퓨샷(Few-shot) 전략
- **원칙:** 정해진 에피소드를 하드코딩하지 않고, LLM이 **상황의 유연성**을 가지도록 한다.
- **퓨샷 프롬프트 활용:** 시스템 프롬프트 내에 고정된 사건을 주는 것이 아니라, **"사소한 일상 속 균열을 포착하는 문체와 감정 묘사의 톤앤매너"**를 보여주는 예시(Few-shot)를 심어둔다.

### 💡 퓨샷 예시 템플릿 (참고용)
> **[입력 데이터 예시]**
> - 대상: 3년 차 회사원
> - 감정: 지독한 권태와 짜증
> - 상황: 월요일 아침 꽉 막힌 출근길
> 
> **[출력 톤앤매너 예시]**
> "지하철 손잡이를 잡은 손가락 마디마디에 힘이 빠졌다. 옆 사람의 어깨가 부딪쳐도 화를 낼 에너지조차 남지 않은 월요일 아침. 스마트폰 화면 속 멈춰 있는 시계를 보며, 문득 내가 이 도시의 거대한 부품 하나로 닳아 없어지고 있다는 서늘한 자각이 스친다."

## 5. 백엔드/에이전트 역할 분담
- **입력 분석기:** 사용자가 선택한 `[대상-감정-상황-장르]`를 조합하여 LLM 시스템 프롬프트의 맥락(Context)을 구성한다.
- **서사 생성기 (LLM):** 퓨샷의 문체 가이드를 바탕으로 첫 오프닝 시나리오와 몰입감 있는 선택지(최소 2~3개)를 실시간으로 렌더링한다.
- **선택지 분기 처리:** 플레이어의 선택에 따라 감정의 파동이 누적되며 다음 챕터로 유기적으로 이어지도록 상태(State)를 관리한다.
