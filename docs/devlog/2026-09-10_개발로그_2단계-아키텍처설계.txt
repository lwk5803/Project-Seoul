[1. 현재 단계 목표]

1단계에서 백엔드(FastAPI) / 프론트엔드(Next.js) 뼈대를 세웠다.
그런데 그 다음에 바로 "AI가 이야기를 만들어주는 기능"을 짜기 시작하면
십중팔구 이런 일이 벌어진다.

  - 프론트가 기대하는 데이터 이름과 백엔드가 보내는 이름이 다르다
  - AI가 HP를 마음대로 바꿔버려서 게임 밸런스가 무너진다
  - 어디까지 만들었는지 헷갈려서 같은 걸 두 번 짠다

그래서 이번 단계는 코드를 한 줄도 안 짜고, 대신 "약속"을 문서로 못 박았다.

이번 단계 목표:
  - 전체 데이터 흐름 확정 (브라우저 -> FastAPI -> AI -> DB)
  - 게임 규칙 확정 (능력치, 주사위, 자원, 게임오버 조건)
  - DB 테이블 구조 확정 (7개 테이블 + 보안 정책)
  - 프론트/백엔드가 주고받을 API 형식 확정 (계약서)
  - AI 멀티 에이전트 구조 확정 (LangGraph 노드 6개)
  - Step 1~12 개발 순서 확정
  - 프론트/백엔드 세션에 넘길 작업 지시서 작성

산출물: docs/ 폴더에 문서 8종


[2. 사용한 기술/핵심 개념 (비유 설명 포함)]

(1) API 계약서 (docs/04)
    = 건물 시공 도면.
    이 프로젝트는 프론트엔드 담당 세션과 백엔드 담당 세션이 따로 작업한다.
    두 세션은 서로의 코드를 볼 수 없다. 그래서 "이 주소로 요청하면
    이런 모양의 데이터를 준다"는 약속문이 반드시 필요하다.
    도면 없이 두 팀이 각자 벽을 쌓으면, 만나는 지점에서 절대 안 맞는다.

(2) 구조화 출력 (Structured Output)
    = AI에게 "자유롭게 답해"가 아니라 "이 빈칸을 채워"라고 시키는 방식.
    "판정이 필요한가? (예/아니오), 어떤 능력치? (6개 중 하나), 난이도? (4개 중 하나)"
    이렇게 객관식으로 물으면 AI가 엉뚱한 형식으로 답할 수가 없다.
    LangChain의 with_structured_output()이 이 역할을 한다.

(3) SSE (Server-Sent Events)
    = 라디오 방송.
    방송국(서버)이 계속 말하고, 청취자(브라우저)는 듣기만 한다.
    AI가 글을 다 쓸 때까지 10초를 기다리게 하면 유저는 떠난다.
    그래서 한 글자씩 만들어지는 대로 흘려보낸다.
    WebSocket(전화 통화, 양방향)도 있지만 1인 플레이에는 과하다.

(4) RLS (Row Level Security)
    = 표의 각 줄마다 자물쇠를 다는 것.
    Supabase에서 이걸 안 켜면, A유저가 B유저의 캐릭터를 볼 수 있다.
    가장 흔한 사고라서 DB 설계 문서에 정책 SQL을 미리 적어뒀다.

(5) pgvector / 임베딩
    = GM의 "기억 서랍".
    문장의 의미를 1536개의 숫자 좌표로 바꿔 저장한다.
    비슷한 의미의 문장은 좌표가 가깝다.
    그래서 "알바생"으로 검색하면 "김수진"이 나온 장면도 찾아진다.
    키워드가 아니라 의미로 찾는 검색이다.

(6) 멀티 에이전트 (LangGraph)
    = 한 명에게 요리+서빙+계산을 다 시키지 않고 나누는 것.
    판정관 / 주사위 / 기억검색 / 이야기꾼 / 기록원 / 검증기
    이렇게 6개 노드로 나눴다. 문제가 생기면 그 노드만 고치면 된다.


[3. 작성/수정된 핵심 코드]

이번 단계는 코드가 아니라 문서가 산출물이다.
다만 다음 단계에서 그대로 코드가 될 "설계 스니펫"을 적어둔다.

[주사위 판정 - 파이썬이 굴린다 (AI에게 안 맡긴다)]

    def roll_dice(stat_value: int, difficulty: str) -> DiceCheck:
        """
        주사위를 굴리고 성패를 판정한다.
        AI를 쓰지 않는 이유: AI는 진짜 무작위를 만들지 못하고,
        극적이거나 유저에게 유리한 숫자를 '고르는' 경향이 있다.
        """
        dice = random.randint(1, 20)          # 순수 주사위값
        modifier = stat_value * 2             # 능력치 보정
        total = dice + modifier
        dc = DIFFICULTY_TABLE[difficulty]     # easy=10 normal=14 hard=18 extreme=22

        if dice == 20:    outcome = "critical_success"
        elif dice == 1:   outcome = "critical_failure"
        elif total >= dc: outcome = "success"
        else:             outcome = "failure"

[AI의 제안을 그대로 믿지 않고 검증한다]

    def apply_state_changes(session, archivist_output):
        """
        AI의 '제안'을 실제 상태에 반영한다.
        AI가 '당신은 100억을 얻었습니다'라고 해도
        파이썬이 상한선에서 잘라낸다.
        """
        hp_delta = clamp(archivist_output.resource_delta.hp, -40, 30)   # 한 턴 변화 상한
        new_hp = clamp(session.resources.hp + hp_delta, 0, session.resources.max_hp)

[SSE 이벤트 규격 - 프론트와의 약속]

    turn_started      -> {"turn_id","turn_number"}
    dice_roll         -> {"stat","dice","modifier","total","difficulty","outcome"}
    narration_delta   -> {"text": "..."}   (여러 번, 그대로 이어붙이면 전체 서술)
    state_patch       -> {"resources":{"mental":-3}, "world_state":{...}}
    turn_completed    -> 최종 전체 상태 (프론트는 이 값으로 화면을 덮어쓴다)
    error             -> {"code","message"}

    * 중간 이벤트를 놓쳐도 turn_completed로 화면이 DB와 다시 맞춰진다.
      "안전장치를 먼저 설계한다"가 이번 단계의 핵심이었다.

[턴 잠금 - 전송 버튼 연타 방지]

    행동 요청 도착
      -> game_sessions.status 를 'active' -> 'processing' 으로 조건부 UPDATE
      -> 못 바꿨다? = 이미 처리 중 = HTTP 409 반환
      -> 처리가 끝나면(성공/실패 무관, finally 블록에서) 다시 'active'

    * 여기서 finally를 빼먹으면 세션이 영원히 잠긴다.
      유저 입장에서는 "게임이 먹통이 됐다"가 된다.

[5. 오늘의 학습 포인트]

포인트 1. AI에게 시킬 일과 시키면 안 되는 일을 나누는 게 설계의 핵심이다.
  주사위 굴리기, 숫자 계산, 상태 저장은 절대 AI에게 맡기지 않는다.
  AI는 "그럴듯한 말을 만드는 기계"이지 계산기가 아니기 때문이다.
  AI는 묘사만 하고, 판단과 계산은 파이썬이 한다.

포인트 2. 프론트와 백엔드의 타입은 사람이 맞추면 반드시 어긋난다.
  Pydantic 모델 -> OpenAPI 문서 -> TypeScript 타입을 자동 생성하는 파이프라인을
  Step 3에 넣었다. 백엔드가 필드명을 바꾸면 프론트에서 컴파일 에러가 난다.
  "에러가 나는 게 성공"이다. 어긋남을 유저가 발견하기 전에 잡아주기 때문이다.

포인트 3. 실패했을 때의 동작을 성공 코드보다 먼저 설계해야 한다.
  AI API는 생각보다 자주 실패한다(타임아웃, 한도초과, 장애).
  노드별로 "실패하면 어떻게 할지"를 미리 표로 정리했고,
  특히 세션 잠금을 finally로 반드시 푸는 규칙을 명시했다.
  이걸 나중에 붙이려고 하면, 이미 유저가 먹통을 경험한 뒤다.
