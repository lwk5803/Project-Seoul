[1. 현재 단계 목표]

AI TRPG 게임 마스터 서비스를 만들기 위한 첫 벽돌 쌓기 단계.
게임 로직은 아직 없지만, 앞으로 모든 기능이 올라갈 뼈대를 완성함.

- 백엔드(FastAPI) 서버가 켜지고, "살아있는지" 확인할 수 있는 상태
- Supabase(데이터베이스) 연결에 필요한 설정 구조 준비
- 프론트엔드(Next.js) 프로젝트 생성 및 기본 실행 확인
- 앞으로 AI 에이전트 로직과 데이터 모델이 들어갈 폴더 구조 미리 준비
- (추가) Supabase가 API 키 이름 체계를 바꿔서, 그에 맞춰 설정을 최신화함


[2. 사용한 기술/핵심 개념 (비유 설명 포함)]

- FastAPI = 가게의 정문 + 주문 접수대. main.py가 서버를 켜는 전원 스위치.
- 라우터(Router) = 창구별 담당 직원. 지금은 /health 창구 하나 (서버 생존 확인).
- pydantic-settings = 비밀 열쇠를 안전하게 꺼내 쓰는 금고. .env에 넣어둔 Supabase
  키를 config.py가 안전하게 꺼내옴. .env는 .gitignore로 막혀있어 깃허브에 노출 안 됨.
- Next.js App Router = 완성된 매장 인테리어 템플릿. layout.tsx = 공통 뼈대,
  page.tsx = 첫 페이지 내용(아직 기본 시작화면 그대로).
- Supabase 키 체계 변경 = 열쇠 이름표를 다시 붙인 것. 예전엔 "anon(익명) 키" /
  "service_role(관리자) 키"라고 불렸는데, 이름만 봐서는 뭐가 위험한 키인지
  헷갈리기 쉬웠다. 그래서 "publishable(공개해도 되는 정문 열쇠)" /
  "secret(절대 노출 금지인 금고 열쇠)"로 이름을 더 직관적으로 바꿨다.
  여기에 로그인 토큰을 검증할 때 쓰는 JWKS 주소(공개 열쇠 목록 창구)도 추가됨.


[3. 작성/수정된 핵심 코드]

[backend/app/main.py]
from fastapi import FastAPI
from app.api.routes.health import router as health_router

app = FastAPI(title="Project-Seoul API")
app.include_router(health_router)

@app.get("/")
def root():
    return {"message": "Project-Seoul 백엔드가 실행 중입니다."}

[backend/app/api/routes/health.py]
from fastapi import APIRouter

router = APIRouter()

@router.get("/health")
def health_check():
    return {"status": "ok"}

[backend/app/core/config.py]  ※ Supabase 새 키 체계 반영(수정됨)
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    supabase_url: str
    supabase_publishable_key: str
    supabase_secret_key: str
    supabase_jwks_url: str = ""
    supabase_db_password: str = ""

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=False,
    )

settings = Settings()

(publishable_key / secret_key는 기본값이 없어서 .env에 값이 없으면 서버 실행 시
 바로 에러가 난다. jwks_url은 당장 인증 기능을 안 쓰므로 기본값 ""을 줘서
 비워둬도 서버가 켜지게 했다.)

[backend/.env.example]  ※ 수정됨
SUPABASE_URL=
SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SECRET_KEY=
SUPABASE_JWKS_URL=
SUPABASE_DB_PASSWORD=

[4. 동작 확인 방법]

[백엔드 - Windows cmd]
cd backend
venv\Scripts\activate
uvicorn app.main:app --reload

- http://localhost:8000        -> {"message": "Project-Seoul 백엔드가 실행 중입니다."}
- http://localhost:8000/health -> {"status": "ok"}
- http://localhost:8000/docs   -> 자동 생성된 API 문서(Swagger UI)

(추가 확인 - Supabase 새 키 설정 반영 확인)
1) backend/.env.example을 복사해서 backend/.env로 만들고
   SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, SUPABASE_SECRET_KEY 값을 채운다.
2) backend 폴더에서:
   python -c "from app.core.config import settings; print(settings.supabase_url)"
3) 에러 없이 URL이 출력되면 정상.

[프론트엔드]
cd frontend
npm run dev

- http://localhost:3000 -> Next.js 기본 시작 화면 확인


[5. 오늘의 학습 포인트]

- 비밀 정보(API 키, DB 비밀번호)는 .env로 분리하고 .gitignore로 보호하는 게
  기본 보안 습관이다.
- FastAPI는 기능마다 라우터 파일을 나눠서 관리하면 나중에 코드가 안 엉킨다.
- agents/, models/ 같은 빈 폴더를 미리 만들어두면 실제 로직을 짤 때 헷갈리지 않는다.
- 프론트/백엔드는 완전히 분리된 별개의 프로젝트이며, 서로 다른 포트(3000, 8000)에서
  각자 실행된다.
- 외부 서비스(Supabase)가 API 체계를 바꾸는 일은 실제로 종종 있고, 그럴 때는
  .env.example(견본)과 config.py(설정 읽는 코드) 두 곳을 같이 맞춰줘야 한다.
- 기본값(예: "")을 주느냐 안 주느냐로 "필수 값"과 "나중에 채워도 되는 값"을
  구분할 수 있다.
