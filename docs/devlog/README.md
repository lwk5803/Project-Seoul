# 개발 로그 / 블로그 초안 보관함

각 작업 단계가 끝날 때마다 쓰는 기록을 모아두는 곳입니다.
**git으로 추적되므로 데스크톱·노트북 어디서 작업하든 그대로 따라옵니다.**

---

## 파일 두 종류

| 파일 | 용도 | 누가 쓰나 |
|---|---|---|
| `<날짜>_개발로그_<단계>.txt` | 내가 나중에 다시 볼 학습/기록용 | **모든 작업 세션 필수** (프론트/백엔드/아키텍처) |
| `<날짜>_티스토리_블로그초안_<단계>.md` | 티스토리에 바로 붙여넣을 글 | **프로젝트 공부 세션에서만** |

> ⚠️ 작업 세션은 **개발 로그만** 씁니다. 블로그 초안은 쓰지 않습니다.
> 블로그 초안은 공부 세션이 여기 쌓인 개발 로그를 재료로 나중에 작성합니다.
> 그래서 개발 로그에 "왜 그렇게 짰는지"를 충분히 적어두는 것이 중요합니다.

### 이름 규칙
```
2026-09-10_개발로그_2단계-아키텍처설계.txt
2026-09-10_티스토리_블로그초안_2단계-아키텍처설계.md
└─ 날짜 ──┘ └─ 종류 ────┘ └─ 단계번호-주제 ─┘
```
- 날짜는 `YYYY-MM-DD`
- 단계 번호는 **블로그 편 번호**와 맞춥니다. (2단계 = 블로그 (2)편)
- 파일 목록이 날짜순으로 정렬되도록 날짜를 맨 앞에 둡니다.

---

## 왜 `Claude outputs/`가 아니라 여기인가

- `Claude outputs/`는 `.gitignore`에 막혀 있어 **다른 컴퓨터로 따라가지 않습니다.**
- 개발 로그와 블로그 초안에는 비밀키가 없으므로 git에 올려도 안전합니다.
- `Claude outputs/`는 커밋하면 안 되는 **개인 메모 전용**으로 남겨둡니다.

---

## 작성 규칙

작성 형식과 시점은 프로젝트 루트의 [`CLAUDE.md`](../../CLAUDE.md) **5장**에 있습니다.

> 💡 핵심: **한 단계가 끝나면 개발 로그를 그 자리에서 바로 씁니다.** 나중에 몰아서 쓰면
> "왜 그렇게 짰는지"를 이미 잊어버려서 기록의 가치가 사라집니다.
