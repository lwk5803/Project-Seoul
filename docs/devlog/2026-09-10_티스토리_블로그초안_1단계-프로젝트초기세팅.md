### 🛠️ 1. 왜 FastAPI인가

파이썬 웹 프레임워크는 Flask, Django 등 여러 선택지가 있는데, FastAPI를 고른 이유는 두 가지다.

* **비동기(async) 처리가 기본 지원된다** — AI TRPG는 "입력 → AI 응답 대기 → 진행"의 반복인데, 응답을 기다리는 동안 서버가 멈추면 안 된다.
* **Pydantic과 궁합이 좋다** — "캐릭터 정보", "세션 상태" 같은 복잡한 데이터가 잘못된 형식으로 오면 바로 에러로 잡아준다.

비유하면 FastAPI는 **가게 정문이자 주문 접수대**다. `main.py`는 이 가게의 전원 스위치다.

```python
# backend/app/main.py
from fastapi import FastAPI
from app.api.routes.health import router as health_router

app = FastAPI(title="Project-Seoul API")
app.include_router(health_router)

@app.get("/")
def root():
    return {"message": "Project-Seoul 백엔드가 실행 중입니다."}
```

한 줄씩 보면:

* `FastAPI(title="...")` — 가게(서버 인스턴스)를 하나 연다. `title`은 `/docs` 자동 문서의 제목이 된다.
* `include_router(health_router)` — 따로 만든 "창구"(라우터)를 가게에 연결한다.
* `@app.get("/")` — "이 주소로 GET 요청 오면 이 함수 실행"이라는 꼬리표(데코레이터)다.
* `def root(): return {...}` — 딕셔너리를 리턴하면 FastAPI가 알아서 JSON으로 바꿔서 응답한다.

### 🧩 2. 라우터를 왜 파일로 쪼갰나

"회원가입", "게임 세션", "AI 대화" 처럼 기능이 계속 늘어난다.

이걸 `main.py` 한 파일에 몰아넣으면 파일이 수천 줄이 되고, 어디를 고쳐야 할지 찾기가 지옥이 된다.

그래서 FastAPI는 **라우터(Router)** 단위로 기능을 쪼갤 수 있게 해준다. 비유하면 라우터는 **창구별 담당 직원**이다.

지금은 "서버가 살아있는지 확인"만 하는 `/health` 창구 하나만 만들어뒀다.

```python
# backend/app/api/routes/health.py
from fastapi import APIRouter

router = APIRouter()

@router.get("/health")
def health_check():
    return {"status": "ok"}
```

* `router = APIRouter()` — `app`과 비슷한, 독립된 미니 서버 조각이다. 나중에 `include_router()`로 본체에 붙인다.
* `/health` 요청에 `{"status": "ok"}`만 돌려준다. 배포 후 "서버가 살아있는지" 모니터링 도구가 계속 두드리게 될 창구다.

### 🔐 3. Supabase 연결 정보를 코드에서 분리하는 이유

Supabase 주소(URL)와 API 키를 코드에 직접 적어두면, 깃허브에 올리는 순간 전세계에 그대로 노출된다.

그래서 `pydantic-settings`의 `BaseSettings`로, `.env` 파일에 넣어둔 값만 안전하게 불러오게 했다.

```python
# backend/app/core/config.py
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    supabase_url: str
    supabase_publishable_key: str
    supabase_secret_key: str
    supabase_jwks_url: str = ""
    supabase_db_password: str = ""

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=False,
    )

settings = Settings()
```

* `BaseSettings`를 상속하면, `.env`에 적힌 값을 자동으로 채워주는 특수 능력이 생긴다.
* `supabase_url: str`처럼 **기본값이 없는 항목**은 `.env`에 값이 없으면 서버 실행 즉시 에러가 난다. 설정을 빠뜨렸다는 걸 바로 알려주려는 의도다.
* `supabase_jwks_url: str = ""`처럼 **기본값 `""`이 있는 항목**은 당장 비워둬도 서버가 정상적으로 켜진다.
* `settings = Settings()` — 이 시점에 `.env`를 실제로 읽어서 값을 채운다. 다른 파일에서는 `from app.core.config import settings`로 가져다 쓴다.

> 💡 `.env`는 반드시 `.gitignore`에 등록해서 커밋 대상에서 제외해야 한다. 깃허브에는 `.env.example`처럼 빈 서식만 올라가야 안전하다.

### 🔄 4. 작업 도중 생긴 변화 — Supabase가 API 키 이름을 바꿨다

원래는 `anon` 키와 `service_role` 키였는데, 이 이름이 용도를 잘 설명하지 못했다.

* `anon`은 "익명"이라는 뜻이지만, 사실 프론트엔드에 노출해도 되는 "공개용 키"였다.
* `service_role`은 관리자 키인데, 이름만 봐서 위험도가 안 느껴졌다.

그래서 이렇게 바뀌었다.

* **publishable 키** — 공개해도 되는 키. **가게 정문 열쇠**에 가깝다.
* **secret 키** — 절대 노출 금지. **금고 열쇠**다.
* **JWKS URL** — 로그인 토큰이 진짜인지 검증할 때 쓰는 주소. 아직 안 쓰니 기본값을 비워뒀다.

```
# backend/.env.example
SUPABASE_URL=
SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SECRET_KEY=
SUPABASE_JWKS_URL=
SUPABASE_DB_PASSWORD=
```

배운 점: 외부 서비스가 스펙을 바꾸면 **견본 파일(`.env.example`)과 설정 코드(`config.py`)를 같이 맞춰야** 한다. 하나만 고치면 "값은 넣었는데 왜 에러가 나지?" 하는 상황이 온다.

### 🎨 5. Next.js로 프론트엔드 프로젝트 생성하기

`create-next-app`으로 **TypeScript + Tailwind CSS + App Router** 조합을 새로 만들었다.

* **TypeScript** — 실수를 코드 실행 전에 잡아주는 "맞춤법 검사기" 같은 존재.
* **Tailwind CSS** — `className="bg-blue-500 text-white p-4"`처럼 태그에 바로 스타일을 붙이는 방식. 파일을 왔다갔다 안 해도 된다.
* **App Router** — `layout.tsx`는 공통 뼈대(골조), `page.tsx`는 실제 화면(진열 상품)을 담당한다.

아직 기본 시작 화면 그대로지만, 백엔드(8000번 포트)와 분리된 3000번 포트에서 독립적으로 도는 것까지 확인했다.
