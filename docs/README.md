# Project-Seoul 설계 문서

이 폴더는 **"코드를 짜기 전에 정하는 약속"**을 모아둔 곳입니다.

집을 짓기 전에 설계도를 그리는 것과 같습니다.
설계도 없이 벽돌부터 쌓으면, 나중에 "화장실 위치가 잘못됐네" 하고
이미 쌓은 벽을 부숴야 합니다. 그게 개발에서 가장 비싼 실수입니다.

이 문서들은 **프론트엔드 세션 / 백엔드 세션이 각각 따로 작업해도
서로 어긋나지 않게** 만드는 공통 약속문입니다.

## 이 문서들의 우선순위

> 🎯 **04-API 계약서가 가장 중요합니다.**
> 프론트엔드 세션과 백엔드 세션은 서로의 코드를 보지 못합니다.
> 두 세션이 유일하게 공유하는 것이 이 계약서입니다.
> **계약서를 바꿀 때는 반드시 이 아키텍처 세션에서 바꾸고,
> 양쪽 세션에 동시에 알려야 합니다.**

## 문서 수정 규칙

- 문서를 고치면 파일 하단의 `변경 이력`에 날짜와 이유를 한 줄 추가한다.
- 01번 8장(확정 기술 결정)·9장(환경변수 이름표)은 **각 세션이 구현 전에 반드시 확인**한다. 여기와 다르게 짜지 않는다.
- 코드와 문서가 다르면 **문서가 틀린 것**으로 간주하고 문서를 고친다.
  (단, 04-API 계약서만은 반대다. 계약서가 기준이고 코드가 따라간다.)
