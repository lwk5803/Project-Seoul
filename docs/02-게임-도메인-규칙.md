# 02. 게임 도메인 규칙

> 🎯 이 문서는 **"게임의 룰북"**입니다.
> 프론트엔드는 이 숫자들을 화면에 그리고,
> 백엔드는 이 숫자들로 계산합니다.
> **여기 적힌 이름(예: `hp`, `mental`)이 코드의 변수명과 1:1로 같습니다.**

---

## 1. 세계관

- **배경**: 2020년대 현대 대한민국, 주 무대는 서울
- **장르**: 도시 미스터리 / 일상 드라마 / 오컬트 (시나리오별로 다름)
- **시점**: 2인칭 ("당신은 지하철 계단을 내려간다") — TRPG의 전통적 GM 화법
- **언어**: 전부 한국어

---

## 2. 능력치 (Stats)

캐릭터는 6개의 능력치를 가집니다. 각 능력치는 **1~5** 사이의 값입니다.

| 코드값(영어) | 표시명(한글) | 무엇에 쓰나 | 예시 상황 |
|---|---|---|---|
| `strength` | 체력 | 몸싸움, 버티기, 힘쓰기 | 문을 부순다, 도망치는 사람을 붙잡는다 |
| `agility` | 민첩 | 도주, 손재주, 회피 | 담을 넘는다, 몰래 물건을 집는다 |
| `intellect` | 지능 | 지식, 추리, 기계 | 암호를 푼다, 신문 기사를 분석한다 |
| `perception` | 감각 | 관찰, 눈치, 직감 | 거짓말을 알아챈다, 숨겨진 문을 찾는다 |
| `charm` | 매력 | 설득, 협상, 호감 | 경비원을 구슬린다, 정보를 얻어낸다 |
| `will` | 의지 | 공포 저항, 집중, 인내 | 끔찍한 광경을 보고 버틴다, 유혹을 뿌리친다 |

### 캐릭터 생성 규칙
- 모든 능력치는 **1에서 시작**
- **추가로 9포인트**를 자유 배분 (최대 5까지)
- 즉, 총합은 항상 `6 + 9 = 15`

```
예시) 체력2 민첩3 지능4 감각3 매력2 의지1  → 합계 15 ✅
```

> 💡 **왜 총합을 고정했나?**
> 유저마다 능력치 총합이 다르면 난이도 밸런스를 맞출 수가 없습니다.
> "모두 같은 예산으로 캐릭터를 산다"고 생각하면 됩니다.

---

## 3. 자원 (Resources)

능력치가 "타고난 재능"이라면, 자원은 "게임 중에 닳고 채워지는 것"입니다.

| 코드값 | 표시명 | 범위 | 설명 |
|---|---|---|---|
| `hp` | 체력 | 0 ~ `max_hp`(기본 100) | 0이 되면 게임 오버(부상/기절) |
| `mental` | 멘탈 | 0 ~ `max_mental`(기본 100) | 공포·스트레스로 감소. 0이면 공황 상태 |
| `money` | 소지금 | 0 이상 (정수, 단위: 원) | 초기값 300,000원 |
| `inventory` | 소지품 | 배열 | `[{ "name": "휴대폰", "quantity": 1, "description": "..." }]` |

### 한 턴 변화량 상한 (⚠️ 중요 — 원칙 2의 구체적 수치)

AI가 아무리 극적인 걸 원해도, 파이썬이 이 범위로 잘라냅니다.

| 항목 | 한 턴 최대 변화 |
|---|---|
| `hp` | -40 ~ +30 |
| `mental` | -40 ~ +30 |
| `money` | -1,000,000 ~ +1,000,000 |
| `inventory` | 한 턴에 최대 3개 추가/제거 |

> 이 상한을 넘는 제안이 오면 → 상한값으로 자르고 **경고 로그를 남깁니다.**
> (조용히 무시하면 나중에 "왜 HP가 안 깎이지?"로 디버깅 지옥이 됩니다.)

## 4. 주사위 판정 (Dice Check)

### 기본 공식

```
굴림값 = 1d20  (1~20 사이 무작위 정수)
최종값 = 굴림값 + (관련 능력치 × 2) + 상황 보정치
성공 조건 = 최종값 >= 난이도(DC)
```

### 난이도(DC) 표

| 난이도 코드 | 표시명 | DC | 예시 |
|---|---|---|---|
| `easy` | 쉬움 | 10 | 잠기지 않은 문을 연다 |
| `normal` | 보통 | 14 | 편의점 알바생에게 정보를 캐낸다 |
| `hard` | 어려움 | 18 | 경찰서에서 자료를 몰래 복사한다 |
| `extreme` | 극한 | 22 | 달리는 차에서 뛰어내려 착지한다 |

### 결과 등급 (Outcome)

| 코드값 | 표시명 | 조건 | 서술 방향 |
|---|---|---|---|
| `critical_failure` | 대실패 | 굴림값이 **1** | 원하는 것도 실패 + 추가 악재 |
| `failure` | 실패 | 최종값 < DC | 실패하고 상황이 나빠짐 |
| `success` | 성공 | 최종값 >= DC | 원하는 대로 됨 |
| `critical_success` | 대성공 | 굴림값이 **20** | 원하는 것 이상의 결과 |

> ⚠️ 대실패/대성공은 **굴림값(순수 주사위)** 기준입니다. 능력치를 더한 최종값이 아닙니다.
> (능력치 5인 캐릭터가 20을 굴렸는데 대성공이 아니면 이상하니까요.)

### 판정이 필요 없는 경우

모든 행동에 주사위를 굴리면 게임이 지루해집니다.
**실패할 여지가 없는 행동은 판정 없이 바로 서술합니다.**

```
"편의점에 들어간다"       → 판정 불필요 (그냥 들어가짐)
"알바생을 설득한다"        → 판정 필요 (매력, 보통)
"주머니에서 휴대폰을 꺼낸다" → 판정 불필요
"어두운 골목에서 미행을 눈치챈다" → 판정 필요 (감각, 어려움)
```

이 판단은 **판정관 AI 노드**가 합니다. (05번 문서 참고)

## 5. 세계 상태 (World State)

세션마다 유지되는 "지금 상황" 정보입니다.

```json
{
  "location": "강남역 11번 출구 앞",
  "datetime_in_game": "2026-03-14 22:40",
  "weather": "비",
  "present_npcs": ["김수진", "정체불명의 남자"],
  "flags": {
    "met_sujin": true,
    "knows_about_the_note": false,
    "police_suspicion": 2
  }
}
```

- `flags`는 **시나리오 진행 상태를 기록하는 스위치**입니다.
  "이 NPC를 만난 적이 있나?", "이 단서를 알고 있나?" 같은 것.
- `flags` 값은 `true/false` 또는 `0~10 정수`만 허용합니다. (자유 텍스트 금지 — AI가 매번 다르게 쓰면 조건 검사가 불가능)

## 6. 캐릭터 직업 (Occupation)

MVP에서는 **자유 입력**이 아니라 **정해진 목록에서 선택**합니다.

| 코드값 | 표시명 | 보너스 |
|---|---|---|
| `office_worker` | 회사원 | 소지금 +200,000 |
| `student` | 대학생 | 지능 +1 (최대 5 초과 가능 없음) |
| `journalist` | 기자 | 감각 +1 |
| `police` | 경찰 | 체력 +1 |
| `freelancer` | 프리랜서 | 매력 +1 |
| `part_timer` | 아르바이트생 | 의지 +1 |

> 💡 **왜 자유 입력이 아닌가?**
> "나는 신이다"라고 직업을 적는 유저가 반드시 나옵니다.
> 그러면 AI가 그 설정을 받아들여 게임 밸런스가 무너집니다.
> 자유도는 **행동 입력**에서 주고, **캐릭터 시트는 통제**합니다.

## 7. 게임 오버 조건

| 조건 | 결과 상태 |
|---|---|
| `hp` = 0 | `ended_defeat` (부상으로 이야기 종료) |
| `mental` = 0 | `ended_defeat` (정신 붕괴로 이야기 종료) |
| 시나리오 목표 달성 플래그 | `ended_victory` |
| 유저가 직접 종료 | `ended_by_user` |
| 최대 턴 도달 (기본 100턴) | `ended_timeout` |

---

## 8. 용어 사전 (코드 변수명 통일용)

| 한글 | 코드값 | 절대 쓰면 안 되는 표현 |
|---|---|---|
| 캐릭터 | `character` | ~~player, pc, hero~~ |
| 게임 세션(한 판) | `session` | ~~game, play, room~~ |
| 턴(한 번의 주고받기) | `turn` | ~~message, round, chat~~ |
| 유저 입력 | `player_input` | ~~prompt, query, message~~ |
| GM 서술 | `narration` | ~~response, answer, output~~ |
| 시나리오 | `scenario` | ~~story, quest, module~~ |

> ⚠️ **이 표가 있는 이유**: 백엔드가 `narration`이라고 짰는데
> 프론트가 `response`라고 기대하면 화면이 빕니다.
> 이름 하나를 통일하는 게 버그 열 개를 막습니다.
